= Shadow Verification Policy (formerly "ATS")
:status: normative
:audience: maintainers, CI authors

== Purpose

Shadow verification tooling (the Idris2 tools under `tools/ct-shadow/` and `verification/idris/`; formerly ATS2) may be used as a *shadow verification tool* to reinforce confidence in the canonical implementation.

Shadow tooling is not part of the trusted computing base.

== Authority

* Shadow output is advisory only.
* Shadow tooling MUST NOT declare artifacts valid or invalid.
* Shadow tooling MUST NOT generate canonical outputs.
* Shadow tooling MUST NOT be required at runtime.

== Allowed Uses

Shadow tooling MAY be used to:

* Check canonicalization idempotence
* Validate semantic equivalence over a declared subset
* Cross-check canonical bytes against spec rules
* Detect inconsistencies between spec and implementation

== Prohibited Uses

Shadow tooling MUST NOT:

* Override SPARK behavior
* Block production builds
* Act as a trust root
* Be referenced as authoritative in governance or legal contexts

== Failure Handling

If shadow tooling disagrees with the SPARK core:

* CI MAY fail
* Human review is REQUIRED
* The SPARK output remains authoritative

== Survivability Requirement

The system MUST function correctly if shadow tooling is removed entirely.
